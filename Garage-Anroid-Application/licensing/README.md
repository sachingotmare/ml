# 30-day trial and installation-bound licensing

Each Android installation creates a random **request code** (`GM1-...`) and a separate random possession secret in Android secure storage. The request code can be shared; the secret must never be shared.

The first successful server registration starts a trial of exactly **30 × 24 hours**, using PostgreSQL/server time, not the phone clock. After that, business API requests (including login) are blocked with HTTP 402 and the app displays an activation screen. A signed license for that request code unlocks access until the issuer-selected expiry. Renewal can extend but never shorten an existing license.

The app requires internet and the garage server throughout; offline licensing is not implemented. Expiry does not delete or modify customer, service, inventory or billing data. Scheduled reminders, server backups and administrative migration/backup commands continue independently.

## 1. Create the issuer keys once, on your trusted licensing computer

Use Node.js 24.13+ and the [PowerShell issuer](License-Issuer.ps1). Keep keys outside the app/project/deployment folder:

```powershell
Set-Location 'C:\GitRepo\ml\Garage-Anroid-Application'
.\licensing\License-Issuer.ps1 -Mode Init -KeyDirectory 'C:\GarageIssuerKeys'
```

Enter a strong passphrase of at least 16 characters. The tool creates:

- `issuer-private.pem`: encrypted Ed25519 private key. Keep it only on the trusted issuer computer; never deploy it, put it in an APK, or send it to a customer.
- `issuer-public.pem`: public verification key. Only this file goes to the server.

On Windows, review and restrict the keys directory ACL to your issuer identity and authorized administrators, for example from an appropriate administrative session:

```powershell
icacls 'C:\GarageIssuerKeys' /inheritance:r /grant:r `
  "$($env:USERDOMAIN)\$($env:USERNAME):(OI)(CI)F" '*S-1-5-32-544:(OI)(CI)F'
```

Check command success and effective permissions. File modes from Node alone do not provide Windows ACL isolation. Keep an encrypted backup of the key and passphrase through your approved process. Losing the private key prevents issuing renewals with its corresponding public key.

Init refuses existing files and project-internal directories. No real issuer keys have been generated by this implementation.

## 2. Deploy the schema and install only the public key

Existing databases require the new `installations` table. Use the regular deployment migration/grant process; do not reset the database or raise runtime account privileges.

The Windows orchestrator now accepts:

```powershell
.\deploy\windows\Deploy-GarageManager.ps1 -Mode Deploy `
  -LicensePublicKeyPath 'C:\Transfer\issuer-public.pem' `
  -DownloadWinSW -CertificateThumbprint '<your existing valid TLS certificate thumbprint>'
```

Other existing deployment parameters still apply. The script validates Ed25519 public-key format, refuses private keys or silently replacing another issuer key, and asks for approval before installing it into the restricted secrets folder and changing only `LICENSE_PUBLIC_KEY_FILE`.

Alternatively, securely copy the public key yourself to:

```text
C:\ProgramData\GarageManager\secrets\issuer-public.pem
```

Set the private server runtime environment:

```dotenv
LICENSE_PUBLIC_KEY_FILE="C:\ProgramData\GarageManager\secrets\issuer-public.pem"
```

Grant the actual Node service identity read access and administrator-only write access, then restart the **GarageManager** service. For Linux/Docker, mount a read-only public-key file and set its corresponding absolute path; no private key is needed there.

If the path is omitted, trials still work, but activation returns a clear setup error. A configured missing, invalid, non-Ed25519 or private-key file fails server startup instead of weakening verification.

## 3. Obtain the request code from the phone

During the trial, use **License / request code** in the app. After expiry the request code appears on the mandatory activation screen. Tap **Share request code with license issuer**, or copy the selectable code.

The phone does not need to generate or know the license signing key. No IMEI, contacts, hardware serial number or additional Android permission is used.

## 4. Generate a license for that request code and expiry

On the issuer computer:

```powershell
.\licensing\License-Issuer.ps1 -Mode Issue `
  -PrivateKey 'C:\GarageIssuerKeys\issuer-private.pem' `
  -RequestCode 'GM1-<complete UUID copied from the phone>' `
  -ExpiresAt '2027-11-01T00:00:00Z' `
  -OutputFile 'C:\GarageIssuerKeys\customer-phone.license'
```

Replace the example request code with the actual one. Expiry must be a future UTC timestamp; `Z` means UTC, so choose the correct instant for your intended local end date. A filename is created only if it does not already exist. Enter the issuer passphrase at the secure prompt; it is passed temporarily through a process environment variable, not command-line arguments, source code or a server API.

Share the generated `GMK1...` token with the intended customer. They paste it into the phone's **License key** field and tap **Activate / renew license**. The server verifies the signature, matching installation ID, future issue/expiry dates and possession secret. Keys for other request codes, tampered keys and expired keys are rejected.

For renewal, issue another token for the **same request code** with a later expiry. No uninstall is needed. If a license is issued during trial, the remaining original trial is not shortened: access remains until the later active trial/license expiry.

## Limits and operational responsibility

- As requested, uninstall/reinstall or clearing app data creates a new installation/request code and may start a new trial. This is **installation licensing, not tamper-proof hardware binding**. Old keys cannot activate the new code.
- Anyone with access to the private issuer key and passphrase can issue licenses. Anyone controlling your server/database can alter server-side entitlements. This is not DRM against the server administrator or a modified backend.
- Keep the server/database and issuer clock correct. Phone-clock changes do not extend server access.
- Preserve `installations` in full PostgreSQL backups. Business JSON exports deliberately exclude licensing state, account credentials and sessions. Restoring a business snapshot into another database does not transfer phone entitlements.
- Public-key rotation and revocation workflows are not automated. Installed expiry dates remain in the database; new renewals must verify with the configured public key. Plan key compromise/rotation with your administrator.
- Google Play release builds require genuine reviewer access. Provide reviewer instructions and a safe test account, and issue a reviewer-installation license if its trial expires. Review current Google Play Billing, subscriptions and payments rules before monetizing or directing users to external payment/key purchases. This feature supplies activation, not payment processing or a policy exemption.
- Native device tests remain necessary: first connection, stored request code, retry, expiry screen, pasting/sharing activation, background/foreground behavior and reinstall.
